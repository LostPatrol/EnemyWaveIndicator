## 实机排除测试

先以房主执行普通任务，等待游戏本身的自然潮，不使用手动刷怪代替自然调度。记录实际潮中心提示是否出现、是否稳定停在原点，以及关闭自然潮选项后是否消失。分别观察少量战士和较高成本敌人的中心球体大小。

然后分别触发：巢主哨卫、无畏蜂拥异虫、育母体死亡释放、两类大水母及岩痘幼虫、看守者召唤、科洛科新芽/果实、掠夺虫、两类蜂巢、酸液虫后、噬岩体孢子、普通巢穴/异骸洞穴掠痕虫、核心岩/核心侵扰、矿化爆发/三提石/除虫器事件、典狱长召唤。**预期这些来源不产生自然潮标记**。这张清单目前是待验收项目，未声称逐项实测。

使用 Custom Difficulty 把召唤物替换成普通战士或其他大怪，再重复上述相应来源；自然调度调用链以外的请求应保持未知/非自然。分别让自然潮和事件重叠，以及播报潮和古脂矿体重叠。当前只应显示前者中的自然请求，不应该把后者任意一波标为自然；独立识别后者两类是尚未完成的要求。

联机：房主/客机安装同版，查看相同中心和规模；修改客机本地开关/文字/颜色，验证独立设置。观察未安装 Mod 的客机、晚加入、重连、往返空间站和新任务；无 Mod 客机不作为显示成功验收对象。最长会话超过 46 分钟时，还需检查日志采样停止与类重载不会影响显示；当前诊断调度有 600 次上限。

## 自然潮提前量诊断

DLL 在自己的安装目录旁自动写 `probe-*.jsonl`。开发者分析命令：

```powershell
node .\scripts\Analyze-NativeTiming.cjs '完整路径\probe-xxx.jsonl'
```

`timing` 数组依次是：合格自然敌人样本数、选中心后到生成最小毫秒数、最大毫秒数、入队到生成最大毫秒数、生成到本 Mod 原生交接最大毫秒数、被过滤的自然请求结果数。计时使用 GetTickCount64，短间隔可能量化为 0。无样本必须先排查 capture_fault、auto_fault、hook_status、调用链和注册时序，不能解释成“零延迟”。

这些值测的是**游戏已经完成实际选点之后**，而非倒计时剩余五秒时的候选，也不是 GPU 首帧。在触发前提前调用原游戏选点/生成函数会消费 RNG 或改变刷怪，不符合观察型 Mod 的范围，因此未采用。即使观测到队列等待超过一秒，也不能推出每波有稳定一秒提前量。后续实验要同时测失败/取消请求和首个真正显示帧，才能决定是否适合加入明确区分的待生成标记。
