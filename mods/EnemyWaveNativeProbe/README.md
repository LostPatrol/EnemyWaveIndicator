# Native component — 0.9.4 baseline and opt-in prediction test

`Build-NativeProbe.ps1 -PredictionTest` enables an isolated `0.9.4-prediction-test.3` experiment. On the authority game thread it obtains the current manager through the game's pure `AFSDGameMode::GetWaveManager` query, reads the stock natural-wave countdown once as it enters the five-second window, reads up to four player root positions, reproduces the farthest-pair sphere, and calls only the two fingerprinted navigation queries already used by the stock selector. It follows the selector's `WorldPrivate -> UWorld+0x120 -> navigation owner+0x420 -> Pathfinder+0x708` lookup and records cumulative player/geometry/navigation/projection/center stage counters. It never calls the natural-wave routine, a spawning routine, or the selector's random-player draw. Type 255 is reserved for the visibly different `[?] PREDICTED NATURAL (~5s)` marker. Normal builds do not compile this runtime path. `Prepare-PredictionTest.ps1` writes only below `agent/codex`; it never changes `dist` or installs into the game.

GameCapture.cpp observes ten audited native sites. Natural waves still require the six-return scheduler/source chain; scripted waves use the exact initiating controller or event class from the shared NwiWaveTypes.h catalog. Five library entrypoints scope source identity, and the shared batch helper supplies the actual selected center. Originals are forwarded once with unchanged arguments. SpawnAttribution.h retains source type/request identity, center and timestamps through queue swap removal. Unknown sources never inherit active natural ownership. See docs/WAVE-TYPES.md for all 39 IDs and the audited non-wave OMEN limitation.

EnemyBuckets.h requires regular registration and excludes small/critter buckets for natural waves. Explicit scripted waves may include registered small enemies; critters and unknown registration remain excluded. AutomaticPresentation.cpp samples reflected bucket and descriptor fields on the verified game thread, accumulates successful base descriptor costs, applies each type's enable setting and writes the Mod's versioned Blueprint handoff, including replicated RegionType. Natural timing and aggregate filtering telemetry remain separate from GPU rendering.

Host Init actors own the replicated controller. On the verified game thread, the native bootstrap accepts only the exact active Space Rig or procedural mission World and waits until that same World contains Mod Hub's live controller. This readiness condition proves that gameplay BeginPlay and the required framework dependency are available without a fixed delay. The first successful check loads the matching InitSpacerig/InitCave class, patches the Mod's NwiPoll function, and spawns Init immediately. Init's authority check and GetActorOfClass guard prevent duplicate controllers when MintCat also initializes the Mod. Asset preparation and the paired Mod Hub SearchForMods + RefreshPages calls each have an eight-attempt safety bound, but no time gate; pending readiness is checked at 250 ms initially and 1 Hz after 60 requests. SearchForMods updates discovery while RefreshPages rebuilds the already-created visible UI. Client local presentation needs the matching Pak. Real network and lifecycle integration remain unverified; all-source support remains incomplete, and predictive markers are experimental rather than a released feature.

The bridge is pinned to the audited game/runtime identities enforced by the source checks. Never weaken those checks or restore the retired JavaScript spawning hooks. Low-frequency diagnostic snapshots have a 600-request limit; this limits telemetry, while per-frame Auto polling continues after binding. Recreated/garbage-collected Blueprint classes still require lifecycle acceptance.
