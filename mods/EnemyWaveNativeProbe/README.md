# Native component — 1.1.1 structural discovery

Version 1.1.1 uses the reviewed shared structural profile. The current audited release baseline is Steam build 26107973; compatible code relocation is discovered at startup without fixed game RVAs. Complete instruction spans, unique candidates, actual calls, queue ABI windows and thread imports remain mandatory. NativeAbi stays `0x10000`, preserving existing classes, settings and save format. The user has confirmed in-game testing of the underlying implementation.

See [Game compatibility](../../docs/GAME-COMPATIBILITY.md) for the binding design, diagnostics, profile refresh and build workflow. Run `node scripts/Test-GameCompatibility.cjs "<game.exe>" "agent/codex/<run>/compatibility.json"` before packaging. Inspection uses the production C++ resolver and does not execute game code.

The archived prediction test.6 remains compiled out of production. Its separate query/selector bindings use older game addresses and are not adapted or covered by production discovery; do not enable `-PredictionTest` for compatibility releases.

Normal builds write only lifecycle and changed startup/fault status to `probe-latest.jsonl` beside the DLL. A new session replaces that file, and a session log is capped at approximately 4 MiB. A failed log open or write disables file logging without stopping the mod. Copy the latest log before restarting when reporting a problem. `Build-NativeProbe.ps1 -Diagnostics` opts into detailed five-second heartbeats and event timing; normal builds omit that telemetry. `-PredictionTest` also enables diagnostics and its separate tests. Prediction statistics and selector hooks are absent from normal builds; generating its experimental Pak label additionally requires the authoring flag `-EwiPredictionTest`.

GameCapture.cpp observes ten audited native sites. Normal waves still require the six-return scheduler/source chain; scripted waves use the exact initiating controller or event class from the shared EwiWaveTypes.h catalog. Five library entrypoints scope source identity, and the shared batch helper supplies the actual selected center. Originals are forwarded once with unchanged arguments. SpawnAttribution.h retains source type/request identity, center and timestamps through queue swap removal. Unknown sources never inherit active normal-wave ownership. See docs/WAVE-TYPES.md for all 47 IDs and the audited non-wave OMEN limitation.

EnemyBuckets.h requires regular registration and excludes small/critter buckets for normal waves. Explicit scripted waves may include registered small enemies; critters and unknown registration remain excluded. AutomaticPresentation.cpp samples reflected bucket and descriptor fields on the verified game thread, accumulates successful base descriptor costs, applies each type's enable setting and writes the Mod's versioned Blueprint handoff, including replicated RegionType. Optional diagnostic timing does not measure GPU rendering.

Host Init actors own the replicated controller. On the verified game thread, the native bootstrap accepts only the exact active Space Rig or procedural mission World and waits until that same World contains Mod Hub's live controller. This readiness condition proves that gameplay BeginPlay and the required framework dependency are available without a fixed delay. The first successful check loads the matching InitSpacerig/InitCave class, patches the Mod's EwiPoll function, and spawns Init immediately. Init's authority check and GetActorOfClass guard prevent duplicate controllers when MintCat also initializes the Mod. Asset preparation and the paired Mod Hub SearchForMods + RefreshPages calls each have an eight-attempt safety bound, but no time gate; pending readiness is checked at 250 ms initially and 1 Hz after 60 requests. SearchForMods updates discovery while RefreshPages rebuilds the already-created visible UI. Client local presentation needs the matching Pak. Real network and lifecycle integration remain unverified; all-source support remains incomplete, and predictive markers are experimental rather than a released feature.

ActiveWorld caches the validated viewport and reads its current World through travel. Missing viewport discovery retries at the startup cadence for eight attempts, then at most once every five seconds until it succeeds. Temporary absence never disables initialization; a failed World bridge still stops further reads. The existing native bootstrap test covers delayed discovery and viewport reacquisition.

The bridge is pinned to the audited game/runtime identities enforced by the source checks. Never weaken those checks or restore the retired JavaScript spawning hooks. Low-frequency lifecycle polling continues after binding alongside per-frame Auto polling. Recreated/garbage-collected Blueprint classes still require lifecycle acceptance.
