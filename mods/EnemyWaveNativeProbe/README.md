# Native component — 0.9.1 test candidate

GameCapture.cpp observes ten audited native sites. Natural waves still require the six-return scheduler/source chain; scripted waves use the exact initiating controller class from the shared NwiWaveTypes.h catalog. Five library entrypoints scope source identity, and the shared batch helper supplies the actual selected center. Originals are forwarded once with unchanged arguments. SpawnAttribution.h retains source type/request identity, center and timestamps through queue swap removal. Unknown sources never inherit active natural ownership. See docs/WAVE-TYPES.md for all 36 IDs and non-EWC limitations.

EnemyBuckets.h requires regular registration and excludes small/critter buckets for natural waves. Explicit scripted waves may include registered small enemies; critters and unknown registration remain excluded. AutomaticPresentation.cpp samples reflected bucket and descriptor fields on the verified game thread, accumulates successful base descriptor costs, applies each type's enable setting and writes the Mod's versioned Blueprint handoff, including replicated RegionType. Natural timing and aggregate filtering telemetry remain separate from GPU rendering.

Host Init actors own the replicated controller. On the verified game thread, the native bootstrap accepts only the exact active Space Rig or procedural mission World and waits until that same World contains Mod Hub's live controller. This readiness condition proves that gameplay BeginPlay and the required framework dependency are available without a fixed delay. The first successful check loads the matching InitSpacerig/InitCave class, patches the Mod's NwiPoll function, and spawns Init immediately. Init's authority check and GetActorOfClass guard prevent duplicate controllers when MintCat also initializes the Mod. Asset preparation and the paired Mod Hub SearchForMods + RefreshPages calls each have an eight-attempt safety bound, but no time gate; pending readiness is checked at 250 ms initially and 1 Hz after 60 requests. SearchForMods updates discovery while RefreshPages rebuilds the already-created visible UI. Client local presentation needs the matching Pak. Real network and lifecycle integration remain unverified; all-source support and predictive markers are not implemented.

The bridge is pinned to the audited game/runtime identities enforced by the source checks. Never weaken those checks or restore the retired JavaScript spawning hooks. Low-frequency diagnostic snapshots have a 600-request limit; this limits telemetry, while per-frame Auto polling continues after binding. Recreated/garbage-collected Blueprint classes still require lifecycle acceptance.
